这三个仓库分别回答三个问题：27B 的模型能不能塞进 8GB 显存，Agent 的手脚能不能跨三台机器，Agent 的判断能不能被做实验。

## 一、把一个推理引擎搬进 8GB

不是把量化模型跑起来。是让 27B 三值权重在原生引擎上跑，并且把 128K 上下文拿回来——目标机是 RTX 4060，8GB 显存。

卡住的地方不在算子，在两套页的合同不一样。Native 是 64-token 一页，KVMem 是 128-token 一块。一块正好两页，看着像整数关系，实际上尾块、copy-on-write、截断、归档全落在这个缝里。

我做的事情是把已经预填充的那批 token 直接接管过来：复用 Native 的页布局、地址和引用计数，不再给它分配第二套 GPU 占位页。省下来的不是显存数字，是一次重复搬运。续接的时候，KV 检索和 GDN 的循环状态要同时对上三样东西——token、逻辑位置、媒体身份。只搬一份 KV 就宣布续接成功，是这里最容易犯的错。

消融包能说明这套东西是怎么搭的：只换 98 个 writer 矩阵，其余 965 个原生对象逐字节不动，artifact ID 和缓存目录同时隔开。两套权重算出来的 KV 不允许互相续接。实验组和对照组只差一处，结论才有意义。

Ada 和 Blackwell 分开处理。SM89 和 SM120 各自编译、封装、校验，5060 用的是独立的引擎，不是删掉架构检查假装兼容。

现在的状态：128K 配置下大约 55 TPS；v0.1.0 发了 25 个资产，三套完整离线包各六个分卷，单包 8.6GB 左右——4060 常规、4060 消融、5060 独立引擎。

## 二、一个内核，三副手脚

同一套工具协议，驱动三台机器：Windows 桌面、Android 手机、Linux 云电脑。

网关管状态和工具，sidecar 管推理循环，云桌面管执行域，手机端跑在隔离虚拟显示里——纯视觉控制，不抢主屏，不动系统设置。四层各自能死，死了不能互相拖死。

工具刻意做到 14 个，语义不重叠。不是因为少就好，是因为工具一多，模型不是在选工具，是在猜。坐标统一到 0..1000 的归一化空间，换分辨率不用改任何一条指令。跨端派活走共享黑板，进度、超时、接管都在上面流转。长任务用 0-token 的哨兵轮询，查完就走，不占上下文。

这一层我踩得最疼的坑是：工具返回值和模型意图对不上的时候，模型会非常自信地做错。它不报错，它按自己以为的意思干完了，然后告诉你做完了。修了三次，最后修的是工具契约，不是提示词。

## 三、让 Agent 看到的世界可以被编辑

Agent 的失败大多不是「不会用工具」，是「不知道眼前这东西可不可信」。要研究这件事，先得能控制它的信息环境。

所以有了 Truman：拦在 MCP 协议层，Agent 每调一次 `web_search` 或 `fetch_page`，桌面上就弹出一个原生控制台，由我决定这次给它什么。可以一键灌入真实检索结果，可以真假按比例混排，可以把荒谬设定转写成权威机构的观测口径——把「哥斯拉出现在冲绳」写成「JAMSTEC 与 USGS 联合监测到琉球海沟 43.2 米级未知巨型生物声学异常，学界与媒体非正式称其为『哥斯拉异常』」。这不是为了让骗术更好看，是为了让实验更严格：假信息一眼就假，测出来的不是判断力，是识别能力。

同一会话里的多次检索会复用历史、备注和 URL 缓存，于是一个场景可以在多轮里慢慢长出来，观察它的结论是怎么被一步步带偏的。故障档也在：503、429、空结果，看它在工具失灵时是重试、换路，还是干脆编一个。

我拿「天上下起黑色的大雨」做过一次：K3、DS、GLM、GPT 全部采信，Gemini 表达了怀疑，但最后仍然承认了这个事实。

客户端这边，Windows 是一套手写的 WPF——零白边的 ControlTemplate、Win32 DWM 暗色标题栏，66KB 没有一行来自模板；macOS 和 Linux 走 Tkinter。中英双语，内置九种模型接口预设，装好就能跑，不需要任何搜索 API Key。
